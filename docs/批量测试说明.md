脚本：`scripts/batch-test.ts`。通过本地后端 `/api/run` 调用模型，复用单任务限制、CoT、超时和 MongoDB 保存逻辑。不使用 TIR，不发送参考答案。

本次参数固定为 `temperature=1, top_p=0.95, top_k=20, max_tokens=8192`。模型地址为 `https://u1114350-c53r-def992c7.bjb1.seetacloud.com:8443/v1`，模型名为 `qwen38-27b-nvfp4`。不会切换页面的默认模型选择或修改 vLLM 启动参数。

首次运行快照题库 ID 与生成参数；再次运行同一目录时沿用快照。每题只提交一次，`failed` 或 `truncated` 均记录后继续下一题，不重试。手动取消或服务重启导致中断时暂停批次。数据库/API 无法访问或无法确认任务身份时也暂停，避免重复提交。

运行示例：

```bash
node --import tsx scripts/batch-test.ts test-results/batch-20260918
```

后台运行由 detached 子进程启动，日志为批次目录中的 `worker.log`，进程号为 `worker.pid`，进度为 `state.json`。完整思考、答案、参数和耗时保存在 MongoDB 的 `runs` 中，按 `state.json` 的 runId 对应；页面测试历史可查看。

停止整个批次：先对 `worker.pid` 中的确切进程发送 SIGTERM，再在页面停止当前题。只结束脚本不会主动停止后端正在生成的题目。异常退出可能留下 `worker.lock`，确认该进程已退出后再清理锁文件恢复；不要在原进程运行时移除锁。

后端必须持续运行，电脑休眠、服务退出会影响测试。轮询进度不代表重新调用模型。
