# 数学测试台：架构与开发者导览

本文面向熟悉 Python、希望快速参与本项目开发的工程师。它说明当前实际架构，而不是模型部署方案。

## 一句话概览

这是一个以 **Node.js + TypeScript** 编写的本机数学大模型测试台：React 页面发起单题或批量测试；Fastify 后端把请求转发给 OpenAI 兼容模型接口；MongoDB 持久化题库、模型配置和完整运行历史。

它不是 Python Web 项目，但模型服务可以是任意语言或框架，只要兼容 `POST /v1/chat/completions` 的流式 SSE 协议。例如 vLLM、SiliconFlow 等。

## 运行拓扑

```text
浏览器（React + Vite，开发端口 5173）
          │  /api 代理
          ▼
Fastify API（Node.js / TypeScript，端口 3100）
  ├── MongoDB：questions / runs / model_configs / model_settings
  ├── 本地 images/：受控图片读取
  └── OpenAI 兼容模型：POST {baseUrl}/chat/completions，SSE
          ▲
          │ reasoning/content 流式分片
          └── 远程或本地模型服务
```

生产式启动时，`npm run build` 会把前端编译到 `dist/`；随后 `npm start` 的 Fastify 进程会同时托管前端静态文件与 API。因此生产形态只需访问 `http://127.0.0.1:3100`。

## 技术栈与 Python 对照

| 本项目 | Python 开发中的近似概念 | 职责 |
| --- | --- | --- |
| Node.js 22 + TypeScript | Python 3 + 类型提示 | 服务端运行时与共享类型 |
| Fastify | FastAPI / Starlette | HTTP 路由、SSE、静态文件 |
| React 19 | Vue/前端框架；无直接 Python 等价物 | 单页交互界面 |
| Vite | 前端 dev server / bundler | 开发热更新与 API 代理 |
| MongoDB Node Driver | PyMongo / Motor | 数据库读写 |
| `fetch` + `ReadableStream` | `httpx` + async iterator | 调用并解析模型 SSE 流 |
| `tsx` | `uv run` / 直接运行源码 | 直接执行 TypeScript |
| Node test runner | `pytest` | 单元测试 |

项目使用 ESM：本地导入 TypeScript 源文件时通常带 `.js` 后缀，例如 `import { infer } from './inference.js'`。这是 TypeScript 编译后 Node ESM 的解析规则，不表示仓库中真的有对应 `.js` 源文件。

## 两条关键数据流

### 单题流式测试

1. 前端在 `web/src/main.tsx` 提交 `POST /api/run`，包含题目 ID、参数、`modelConfigId`。
2. `server/src/index.ts` 校验参数与模型配置，创建一条 `runs` 记录，状态为 `running`。
3. `inference.ts` 读取该配置的 URL、模型名和 API Key，向 `{baseUrl}/chat/completions` 发 OpenAI 兼容流式请求。
4. 上游的 `delta.reasoning`/`delta.reasoning_content` 累积到 `run.reasoning`；`delta.content` 累积到 `run.answer`。
5. 后端每约 2 秒把运行快照写入 MongoDB，同时经 `/api/run` 的 SSE 发给浏览器。
6. 收到 `[DONE]` 后，根据 `finish_reason` 设置 `completed`、`truncated` 或 `failed`，保存最终记录。

设计要点：浏览器只是观察者。浏览器断开不会取消已经开始的模型请求；后端仍会把结果保存到 MongoDB。每个后端进程只允许一个活动任务，避免显存/在线 API 并发失控。

### 模型配置与密钥

`model_configs` 保存 URL、模型名和可选的 API Key；`model_settings` 只保存当前选中配置的 ID。`GET /api/models` 会将密钥剥离，只返回 `hasApiKey`，因此浏览器和 Swagger 不会读到明文。

运行时优先使用配置自身的 API Key；对于初始环境变量地址，`MODEL_API_KEY` 可作为后备。模型地址填写 API 基础路径（例如 `https://api.siliconflow.cn/v1`），后端自动追加 `/chat/completions`。

## MongoDB 数据模型

| 集合 | 主键/索引 | 内容 |
| --- | --- | --- |
| `questions` | `id` 唯一 | 题干、参考答案、标签、图片相对路径 |
| `runs` | `id` 唯一；`questionId + startedAt` | 请求快照、思考、答案、usage、耗时、人工评价 |
| `model_configs` | `id` 唯一；`baseUrl + modelName` 唯一 | 模型连接配置与服务端密钥 |
| `model_settings` | `key` 唯一 | 当前模型选择，键为 `selection` |

`Run` 是最重要的审计实体：它保存本次实际调用的模型 URL/名称、生成参数与请求快照。因此以后编辑配置不会改写历史结果。

服务启动时会把数据库里遗留的 `running` 记录标为 `interrupted`，避免服务重启后将半截任务误认为成功。

## API 与调试入口

启动后可访问：

- 页面（开发）：`http://127.0.0.1:5173`
- 页面/API（构建后）：`http://127.0.0.1:3100`
- Swagger UI：`http://127.0.0.1:3100/docs`
- OpenAPI JSON：`http://127.0.0.1:3100/docs/json`
- 健康检查：`GET http://127.0.0.1:3100/api/health`

`POST /api/run` 的返回类型是 SSE，而不是普通 JSON。事件包括 `started`、`status`、`reasoning_delta`、`answer_delta`、`done` 和 `error`。如果用 Python 调试，可用 `httpx.Client.stream()` 逐行消费；注意前端不会把 API Key 提交给该接口，而是只提交 `modelConfigId`。

```python
# 仅说明 SSE 的消费模式；运行前需已有题目与模型配置 ID
import json
import httpx

payload = {"questionId": "MATH-001", "modelConfigId": "<config-id>", "params": {"max_tokens": 8192}}
with httpx.stream("POST", "http://127.0.0.1:3100/api/run", json=payload, timeout=None) as response:
    response.raise_for_status()
    for line in response.iter_lines():
        if line.startswith("data: "):
            event = json.loads(line[6:])
            print(event["type"])
```

## 批量测试

`scripts/batch-test.ts` 是可配置并发 worker。首次使用一个新目录时，它读取 `model_settings.selectedId`，快照当前选中模型、参数和题库 ID；同目录再次运行会从 `state.json` 续跑，不重复已完成题目。`BATCH_CONCURRENCY` 和服务端 `MAX_CONCURRENT_RUNS` 默认均为 4。

```bash
node --import tsx scripts/batch-test.ts test-results/batch-<name>
```

完整的答案/思考仍写入 MongoDB `runs`；批次目录只保存断点续跑状态。详见 [批量测试说明](批量测试说明.md)。

## 扩展建议

- **增加模型供应商**：优先确认其 OpenAI 兼容性。若 SSE 字段不同，集中改 `inference.ts`，不要污染 UI。
- **增加运行字段或展示**：先改 `shared/types.ts`，再同步 MongoDB 读写、API、前端展示和测试。
- **增加 API**：在 `server/src/index.ts` 新增路由和 JSON Schema；Swagger 会自动生成文档。
- **扩展为多实例后台队列**：当前进程内活动任务池支持单实例并发；多进程或多服务实例共同消费任务时，仍应引入 MongoDB/Redis 的任务状态机与原子领取机制。
- **接入 Python 算法服务**：可作为独立 HTTP 服务，由 Fastify 调用；不要直接把 Python 逻辑塞入前端。若需要异步任务，可让 Python worker 消费显式的队列。

## 已知边界

- 单实例、单活动模型请求；没有用户认证或多租户隔离。
- API Key 在 MongoDB 中由后端保存，但当前没有应用层加密/KMS；数据库访问控制和备份必须按密钥级别保护。
- 模型响应必须支持当前 OpenAI 风格流式格式；工具调用、多模态和 TIR 不在当前范围。
- 前端会轮询 `/api/active-run` 与 `/api/runs`，因此开发日志会周期性出现这两个 GET 请求。
