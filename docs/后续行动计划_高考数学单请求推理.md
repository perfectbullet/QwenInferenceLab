# 后续行动计划：高考数学单请求最快推理

> 目标：在**一次生成（Pass@1）正确率不低于基线**的前提下，缩短单道高考数学题的端到端解题时间。  
> 当前主线：231 单张 RTX 5090 + vLLM + `Inferact/Qwen3.8-27B-NVFP4` + 内置 MTP。  
> SGLang + DFlash：已降为最低优先级。

## 1. 成功标准

候选配置按下面的顺序判断：

1. Holdout 的 Pass@1 不低于 no-spec 基线。
2. 在满足第 1 条的配置中，Time-to-correct 更短。
3. 再比较 TTFT、Decode TPS、显存余量和稳定性。

```text
禁止：仅因 token/s 高就宣布更好。
禁止：在同一题集上调参并报告最终正确率。
```

## 3. 第一阶段：启动前验证

### 3.1 验证 Inferact 工件

```bash
find /data/metahuman_work/models/Inferact/Qwen3.8-27B-NVFP4 \
  -maxdepth 1 -iname '*mtp*.safetensors' -type f
```

完成标准：确认 MTP 文件、config、tokenizer 和 chat template 都在目录内。

### 3.2 建立 no-spec 服务

先不启用投机解码。完成以下检查：

- 服务能启动并返回 `/v1/models`。
- 使用数学题脚本 `--workers 1 --limit 10` 跑通。
- 分别确认 COT 与 TIR 模式能输出非空结果。
- 记录 OOM、`finish_reason=length`、工具调用错误和空输出。

完成标准：连续 10 题无服务崩溃；结果 JSONL 可按题目 ID 复算。

## 4. 第二阶段：选定数学 workflow

固定 no-spec 服务，分别执行：

```text
COT：--mode cot --lang zh --workers 1 --max-tokens 8192
TIR：--mode tir --lang zh --workers 1 --max-tokens 8192
```

使用约 75 题 calibration 集比较：

| 指标 | COT | TIR |
|---|---:|---:|
| Pass@1 |  |  |
| 平均完整耗时 |  |  |
| 截断率 |  |  |
| 空输出 / 工具错误 |  |  |

完成标准：选择“正确率不低且正确答案耗时更短”的一个 workflow。之后 MTP 扫参时不再混用 COT/TIR。

## 5. 第三阶段：MTP 基线

对选定 workflow，启动 MTP：

```json
{"method":"mtp","num_speculative_tokens":3}
```

与 no-spec 在相同 calibration 集比较：

```text
Pass@1
TTFT
完整延迟
输出 token
Decode TPS
截断率
显存占用
MTP acceptance / accepted draft tokens（从服务日志读取）
```

完成标准：Pass@1 不低于 no-spec 且 Time-to-correct 下降；否则保留 no-spec 为生产候选。

## 6. 第四阶段：Holdout 确认

将 275 题划为固定 manifest：

```text
calibration：75 题，用于 workflow 与参数选择
holdout：200 题，只用于最终确认
```

在 holdout 上只跑：

1. no-spec 基线；
2. 通过 calibration 的 MTP 配置。

完成标准：候选配置的 Pass@1 不低于 no-spec；如果下降超过 1 个百分点，暂停采用并人工复核题型分布、截断和判题逻辑。

## 7. 第五阶段：只在有收益证据时扫 MTP window

顺序：

```text
先 3（官方配方）
再在模型支持范围内一次只增加一个候选值
每个候选先跑 calibration，再决定是否进入 holdout
```

不要用 DFlash 的 k=10 经验直接推断 MTP 最优 window；两种 draft 架构、计算方式和额外开销不同。

## 8. 脚本改造待办

当前 `run_model_tir_inference_concurrent.py` 已能用 `--workers 1` 跑单请求，但还应补齐：

- [ ] TTFT：收到首个流式 delta 时记录。
- [ ] 输出 token / Decode TPS：从 usage 或 tokenizer 记录。
- [ ] `finish_reason`：识别长度截断。
- [ ] `final_answer_raw`：提取 `\\boxed{}` 中最终答案。
- [ ] 判题：选择/填空做规则与符号归一化；解答题做最终结论与过程盲评。
- [ ] 每次 run 使用新输出文件，避免脚本跳过已有成功 ID。

完成这些后，`metadata.latency_seconds` 用于单题完整调用耗时；`total_elapsed_seconds` 只用于队列诊断，不能比较单请求速度。

## 9. 双 RTX 5090 DFlash 的后续动作

这是独立研究线，不与 231 单卡 Qwen3.8 基线混在一起。

1. 使用现有 vLLM + DFlash k=10、327.05 tok/s 作为基线。
2. 仅测试 k=12、k=15。
3. 加入同一数学题库的 Pass@1 与 Time-to-correct。
4. 只有正确率不降、总耗时更短时才更新双卡最佳配置。

## 10. 低优先级：SGLang + DFlash / DSpark

暂不做参数深挖。重新启动这条线的条件是：

- vLLM MTP 基线稳定后仍有明确性能缺口；或
- 需要比较 DSpark / GDN state / Anthropic API 等 SGLang 特有能力；或
- 有可复现的相同模型、相同 workload、同等 runtime 参数的对比设计。
