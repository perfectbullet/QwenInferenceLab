# 推测解码部署记录与结论（归档）

> 更新日期：2026-08-18
> 主要工作负载：数学 Thinking / 长推理 / 单请求。
> 主要指标：客户端 Decode TPS、TTFT、完整解题耗时。非高并发吞吐场景。

---

## 0. 一页结论

1. 当前最高已验证记录：**2 × RTX 5090 + vLLM + DFlash + TP=2 + k=10 = 327.05 tok/s**。
2. 双 RTX 5090 没有 NVLink，但在当前单请求 workload 下，TP=2 的计算收益仍超过 PCIe/NCCL 通信成本。
3. DFlash 的 k=10 在两套 GPU 上都优于 k=5；不能只以 acceptance rate 决定参数优劣，应以最终 Decode TPS 与完整任务耗时决定。
4. 现有 SGLang + DFlash 已跑通但只有 66.98 tok/s；该结果保留为历史记录，当前不作为生产方案，也不作为近期优先优化项。
5. 生产候选基线：双 RTX 5090 上的 vLLM + DFlash k=10。后续 k=12 / k=15 只能在数学正确率不下降时才保留。

# 第一部分：重点平台——双 RTX 5090

## 1. 测试对象与口径

### 1.1 模型与硬件

```text
Target：Qwen3.6-35B-A3B-AWQ-4bit
Draft： Qwen3.6-35B-A3B-DFlash

GPU：2 × RTX 5090 32GB
互联：无 NVLink，TP collectives 经 PCIe + NCCL/PYNCCL
目标：单请求、长思考、低并发
```

### 1.2 指标口径

| 指标 | 是否用于性能排序 | 说明 |
|---|---|---|
| 客户端 Avg / P50 / P90 / P95 / P99 Decode TPS | 是 | 当前 GPU / runtime 比较的主口径 |
| TTFT | 是 | 记录交互等待；不能只看 decode |
| 完整解题耗时与数学正确率 | 后续生产排序 | 对高考数学业务，优先级高于纯 TPS |
| 服务端 Avg generation throughput | 否 | 固定统计窗口口径，不等于客户端纯 Decode TPS |
| acceptance length / acceptance rate / accepted throughput | 否 | 用于解释投机解码收益，不是最终速度 |

在标准 speculative accept/reject 过程下，已接受的输出由 target 验证；因此重点是保证配置、采样和评测口径一致，而不是把草稿 token 当成最终输出。

## 2. 当前最佳：vLLM + DFlash，TP=2，k=10

### 2.1 已验证启动命令

```bash
VLLM_USE_FLASHINFER_SAMPLER=0 \
CUDA_VISIBLE_DEVICES=0,1 \
vllm serve /data/metahuman_work/models/Qwen3.6-35B-A3B-AWQ-4bit \
  --served-model-name Qwen3.6-35B-A3B-AWQ \
  --tensor-parallel-size 2 \
  --max-model-len 10240 \
  --max-num-seqs 1 \
  --max-num-batched-tokens 10240 \
  --gpu-memory-utilization 0.88 \
  --speculative-config '{
    "method": "dflash",
    "model": "/data/metahuman_work/models/Qwen3.6-35B-A3B-DFlash",
    "num_speculative_tokens": 10
  }' \
  --attention-backend flash_attn \
  --no-enable-prefix-caching \
  --no-async-scheduling \
  --disable-custom-all-reduce \
  --trust-remote-code \
  --port 8300
```

### 2.2 性能结果

| 指标 | 结果 |
|---|---:|
| Avg Decode TPS | **327.05** |
| P50 | 325.48 |
| P90 | 349.43 |
| P95 | 353.36 |
| P99 | 356.51 |

这是当前全部实测中最高的 Avg Decode TPS、P50、P90、P95 和 P99。

### 2.3 可复现参数摘要

```text
TP=2
max_model_len=10240
max_num_seqs=1
max_num_batched_tokens=10240
gpu_memory_utilization=0.88
DFlash k=10
attention_backend=flash_attn
prefix cache=off
async scheduling=off
custom all-reduce=off
```

## 3. 双 RTX 5090 的 k=5 对照组

| DFlash k | Avg Decode TPS | P50 | P90 | 相对 k=10 |
|---:|---:|---:|---:|---:|
| 5 | 268.49 | 266.19 | 282.34 | -21.81% |
| 10 | **327.05** | **325.48** | **349.43** | 基线 |

结论：在双 RTX 5090 上，k=10 比 k=5 快 **21.81%**；当前推荐 k=10。

### 3.1 k=5 的历史命令备注

历史 k=5 草稿未显式带 `--tensor-parallel-size 2`，但结果被记录为双卡。该结果可作为性能历史对照；如果严格复现，应以启动日志确认 `world_size`、TP rank 与 `tensor_parallel_size`。后续实验以本文件的 k=10 完整命令为标准。

## 4. 双 RTX 5090 的 SGLang + DFlash（已跑通，低优先级）

### 4.1 已跑通命令

```bash
export SGLANG_ALLOW_OVERWRITE_LONGER_CONTEXT_LEN=1

CUDA_VISIBLE_DEVICES=0,1 sglang serve \
  --model-path /data/metahuman_work/models/Qwen3.6-35B-A3B-AWQ-4bit \
  --served-model-name Qwen3.6-35B-AWQ-DFlash-Speculative \
  --speculative-algorithm DFLASH \
  --speculative-draft-model-path /data/metahuman_work/models/Qwen3.6-35B-A3B-DFlash \
  --speculative-num-draft-tokens 16 \
  --tp-size 2 \
  --attention-backend triton \
  --speculative-draft-attention-backend triton \
  --mem-fraction-static 0.70 \
  --max-running-requests 1 \
  --cuda-graph-max-bs-decode 2 \
  --mamba-scheduler-strategy extra_buffer \
  --trust-remote-code \
  --host 0.0.0.0 \
  --port 8300
```

### 4.2 结果与当前定位

| 指标 | 结果 |
|---|---:|
| TTFT Avg | 0.144 s |
| Avg Decode TPS | 66.98 |
| P50 / P90 / P95 / P99 | 67.00 / 67.05 / 67.06 / 67.06 |

现有配置中，vLLM k=10 与 SGLang DFlash 的实际比值为 `327.05 / 66.98 = 4.88`。这只说明两套**当前参数组合**的表现不同，不能推导为 runtime 的理论上限差异。

当前决定：不优先深挖 SGLang + DFlash。仅保留为“已跑通记录”；若未来重新投入，应从同模型、同 k、同 attention backend 可比性和 no-spec 基线开始。

## 5. 双 RTX 5090 的平台结论

与单张 RTX PRO 6000 的 k=10 结果相比：

| 平台 | TP | Avg Decode TPS |
|---|---:|---:|
| RTX PRO 6000 Blackwell 96GB | 1 | 253.21 |
| 2 × RTX 5090 32GB | 2 | **327.05** |

双 RTX 5090 高 **29.16%**。对当前 Qwen3.6-35B-A3B-AWQ + DFlash + 单请求 workload，TP=2 的收益大于 PCIe 通信开销。

# 第二部分：DFlash 参数与指标解释

## 6. k=5 与 k=10 的共同结论

| 平台 | k=5 | k=10 | 提升 |
|---|---:|---:|---:|
| RTX PRO 6000 | 217.42 | 253.21 | +16.46% |
| 2 × RTX 5090 | 268.49 | 327.05 | +21.81% |

较大的 k 会让后段位置的接受率下降，但只要 target 一次验证推进的有效 token 更多，最终 Decode TPS 仍能上升。下一轮应只扫 `k=12` 与 `k=15`，并同时检查数学正确率、TTFT 和完整解题耗时。

## 7. RTX PRO 6000 的 DFlash 服务端指标

### k=5

```text
Avg Decode TPS：217.42
Mean acceptance length：4.07
Avg draft acceptance rate：61.4%
Per-position：83.3% / 68.3% / 60.1% / 53.6% / 41.8%
```

### k=10

```text
Avg Decode TPS：253.21
Mean acceptance length：5.02 ~ 5.62
Avg draft acceptance rate：40.2% ~ 46.2%
Per-position：
83.4% / 68.3% / 58.1% / 51.3% / 45.3% /
39.2% / 33.7% / 31.0% / 27.3% / 24.1%
```

因此，acceptance rate 不是要最大化的 KPI；它是解释“为什么 k 增大后最终速度仍然上升”的诊断指标。

# 第四部分：环境与排障备忘

## 9. vLLM 依赖与运行时注意事项

| 事项 | 结论 |
|---|---|
| FlashInfer | `flashinfer-python` 与 `flashinfer-cubin` 需同为 0.6.14；不长期依赖 `FLASHINFER_DISABLE_VERSION_CHECK=1` |
| `OMP_NUM_THREADS` | 需 unset 或设为合法整数，例如 8 |
| CUTLASS / Quack `ThrMma` | 曾发生于 ll_bf16 router GEMM warmup，不是 DFlash、AWQ、KV cache 或权重问题；当时通过跳过可选 warmup 解决 |
| FlashInfer autotune warning | 无缓存时退回默认 tactics，不是启动失败 |
| generation config | target 默认 `temperature=1.0, top_k=20, top_p=0.95`；正式 A/B 必须一致 |

## 10. SGLang 单卡失败历史

单 RTX 5090、Qwen3.6-35B-A3B-AWQ + DFlash 曾因 hybrid Mamba/linear-attention state cache 显存不足失败。双 5090、TP=2、`mem-fraction-static=0.70`、`max-running-requests=1` 后已跑通。该项不再是当前阻塞点。
