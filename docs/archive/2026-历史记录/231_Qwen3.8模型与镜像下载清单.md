## 0.3 性能排障与 MTP 上线记录（2026-08-19）

### 问题：no-spec 服务只有 ~9.4 tok/s（一道题 5~14 分钟）

排障证据链：

| 证据 | 数值 | 含义 |
|---|---|---|
| 引擎 decode 吞吐 | 9.3~9.6 tok/s | 单请求生成速度，比理论慢约 10 倍 |
| GPU 利用率 / 功耗（生成中） | 20% / 135W（满载 ~600W） | GPU 大部分时间在等 kernel launch |
| 冒烟实测 | MATH-248 耗时 342s、输出空 | 基本不可用 |

### 根因

1. **主因：`--enforce-eager` 关闭 CUDA Graph**。混合 GDN 架构每 token 要串行发起几十个小 kernel（conv1d_update、gated_delta_rule、mrope、layernorm……），eager 模式下 launch 开销完全主导；历史 327 tok/s 快配置均未开 eager。
2. **MTP 未启用**：每 engine step 只出 1 token。官方配方本就是 eager + MTP@3 配对——靠 MTP 拉速度。
3. **死路已排除**：`VLLM_QWEN3_5_GDN_DECODE_KERNEL=fused` 要求 SM100（B200 级），5090 是 SM120 只能 Triton（源码 `_validate_fused_gdn_decode_kernel` 确认）。

### MTP 上线过程（三连 OOM 后成功）

| 尝试 | 结果 |
|---|---|
| ① 去 eager + util 0.90 + MTP@3 | ❌ 加载权重时 CUDA OOM（需 2.37 GiB 仅剩 2.30） |
| ② 官方配方 eager + util 0.95 + MTP@3 | ❌ 同点 OOM——comfyui-h3 占 0.86 GiB 挤爆预算 |
| ③ util 0.98 + expandable_segments | ❌ 启动检查直接拒绝：空闲 30.0 GiB < 0.98×31.36 |
| ④ **暂停 comfyui-h3 + 官方配方** | ✅ 成功 |

关键账目：MTP 版权重加载峰值 ~30.5 GiB；comfyui-h3（ComfyUI main.py，808 MiB）+ MPS（52 MiB）占走 ~0.86 GiB 后物理空闲仅 30.0 GiB——**无论 util 调多少都装不下，必须腾位**。

## 0.4 CUDA Graph 实验成功：当前最快配置（2026-08-19 16:13 起）

在 §0.3 的 MTP@3（eager）基础上继续提速，实验记录：

| 尝试 | 配置 | 结果 |
|---|---|---|
| ⑤ 无 eager + MTP@3 + 16K | ❌ KV cache 张量分配 OOM（差 10 MiB；compile/graph 池先吃显存把 KV 挤爆） |
| ⑥ **无 eager + MTP@3 + 10K + `--max-num-seqs 1`** | ✅ **成功，当前最快** |

关键参数 `--max-num-seqs 1`（源自历史 327 tok/s 配方）：单请求业务把 CUDA Graph capture 限制到 bs=1，graph 池仅占 **0.06 GiB**（对比默认 capture 会吃几 GB）。

### 当前生效启动命令

```bash
docker run -d --gpus all --name vllm-qwen38 \
  -e PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True \
  -v /data/metahuman_work/models/Inferact/Qwen3.8-27B-NVFP4:/model \
  -p 8000:8000 \
  --restart unless-stopped \
  vllm/vllm-openai:qwen38 \
  --model /model \
  --served-model-name qwen38-27b \
  --tensor-parallel-size 1 \
  --max-model-len 10240 \
  --max-num-seqs 1 \
  --kv-cache-dtype fp8 \
  --gpu-memory-utilization 0.95 \
  --reasoning-parser qwen3 \
  --enable-auto-tool-choice \
  --tool-call-parser qwen3_coder \
  --speculative-config '{"method":"mtp","num_speculative_tokens":3}'
```

注意：**无 `--enforce-eager`**；上下文窗口 10,240（题面 + 8192 输出基本够用，但需监控长题截断）。

### 三代配置速度对比（同一道数学题实测）

| 配置 | 客户端速度 | 引擎吞吐 | MTP 接受长度 | 相对原始 |
|---|---:|---:|---:|---:|
| no-spec + eager（0.1 节） | ~9 tok/s（推算） | 9.4 tok/s | — | 1× |
| MTP@3 + eager（0.3 节） | ~25 tok/s | 24.7 tok/s | 3.19 | 2.6× |
| **MTP@3 + CUDA Graph（本节）** | **67.8 tok/s（3.6s/题，含 TTFT）** | — | **3.51** | **7.2×** |

MTP 指标（graph 版）：per-position 接受率 97.1% / 81.4% / 72.9%，avg acceptance rate 83.8%，mean acceptance length 3.51/4。

### 资源占用

- 显存 29.9 / 32.6 GiB（余 ~2.6 GiB，三代中最宽裕）
- KV cache 23,738 tokens（10K 窗口 2.32x 冗余，单请求充裕）
- 启动耗时约 4.5 分钟（含 torch.compile 101s + graph capture 2s）

### 注意事项

1. **10K 窗口约束**：`max_tokens=8192` 输出 + 题面后所剩不多，冒烟时盯紧长题的 `finish_reason=length` 截断；如截断率高需回到 16K 并再想别的显存办法。
2. `max-num-seqs 1` 意味着同时只服务 1 个请求——与单请求评测目标一致，但不能并发复测。
3. 日志提示可用 `--kv-cache-memory=3746446848` 把空闲显存再压给 KV（当前 KV 2.69 GiB / 可到 3.49 GiB）；非必需。
4. spec-decode + FlashInfer 下 cudagraph 自动降为 PIECEWISE 模式（非 FULL），属预期行为。
