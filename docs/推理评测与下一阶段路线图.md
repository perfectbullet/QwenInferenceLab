# 推理评测与下一阶段路线图

> 合并原“下一阶段推理部署与推测解码路线图”和“提示词：冒烟与 MTP 对比”。
> 当前主线：比较 231 上 Qwen3.6 与 Qwen3.8 的高考数学正确率和正确答案耗时。

## 1. 北极星指标

候选配置按以下顺序排序：

1. Pass@1 不低于基线。
2. 在正确率达标的配置中，Time-to-correct 最短。
3. 前两项接近时，再比较 TTFT、Decode TPS、显存、功耗和稳定性。

| 指标 | 定义 |
| --- | --- |
| Pass@1 | 每题只生成一次的最终答案正确率 |
| Time-to-correct | 答对题目的端到端时间，包含 TTFT、思考和正文 |
| Decode TPS | 输出阶段速度，用于解释运行时收益 |
| 截断率 | `finish_reason=length` 或输出预算耗尽的比例 |

## 2. 当前基线

| 模型 | 231 配置 | 当前记录 |
| --- | --- | ---: |
| Qwen3.6-35B-A3B-NVFP4 | MTP@4、20K、Text Only | 约 400 tok/s |
| Qwen3.8-27B-NVFP4 | MTP@3、32K、eager、Text Only | 40+ tok/s |

这两条速度不是统一 benchmark 结果。第一优先级是用同一批题、同一采样和同一客户端重新测量，而不是继续扫参数。

## 3. 评测集与实验纪律

建议将 275 题题库固定拆分为：

| 集合 | 建议规模 | 用途 |
| --- | ---: | --- |
| Calibration | 75 题 | 选择模型、workflow、MTP window 和运行时参数 |
| Holdout | 200 题 | 只验证最终候选，不参与调参 |

保持原始 JSONL 只读，只保存题目 ID manifest。按选择、填空、解答以及知识点分层；固定随机种子。

每轮要求：

- 并发固定为 1，单题独立计时。
- 采样参数、提示词、最大输出和 thinking 设置完全一致。
- COT 只与 COT 比，TIR 只与 TIR 比。
- 输出写入新的 JSONL，不覆盖旧结果。
- 一轮只改变一个变量。
- 所有错误、空输出、截断和重试都保留，不能从统计中静默删除。

## 4. 冒烟流程

### 4.1 服务检查

```bash
nvidia-smi
curl -fsS http://192.168.8.231:8200/health
curl -fsS http://192.168.8.231:8200/v1/models
```

先跑 10 题 COT；TIR 只有在需要工具执行时再跑。每轮汇总：

- 非空输出数。
- `\boxed{}` 最终答案提取率。
- 正确题数与 Pass@1。
- 平均/中位 TTFT、端到端耗时、Decode TPS。
- 截断数、5xx、OOM、服务重启数。
- MTP mean acceptance length 与各位置接受率。

已知失败模式：部分多问综合题会出现思考反刍，增加 2K/4K/8K 输出预算仍可能全部撞顶。应如实记为失败，而不是为单题不断放宽预算。

### 4.2 no-spec 与 MTP 对比

对每个模型使用相同服务参数，仅切换 `--speculative-config`：

```text
Qwen3.6：no-spec ↔ MTP@4
Qwen3.8：no-spec ↔ MTP@3
```

10 题只用于发现崩溃、空输出和明显回退，不下最终质量结论。通过后再跑 Calibration。

## 5. 执行阶段

### Phase 0：冻结环境

- 记录 Docker image tag 与 digest、驱动、CUDA、vLLM、FlashInfer、PyTorch 和 Transformers。
- 保存两条当前启动命令及模型文件 revision/hash。
- 同一配置重复 3 次；速度波动超过 5% 时先排除噪声。

### Phase 1：统一复测 Qwen3.6 与 Qwen3.8

固定 231、单请求、同一 10 题冒烟集：

1. 复现 Qwen3.6 约 400 tok/s 服务。
2. 复现 Qwen3.8 40+ tok/s 服务。
3. 记录逐题正确率、TTFT、输出 token、总时间和显存。
4. 确认结果可复现后再进入 75 题 Calibration。

完成标准：连续完成全部请求，无 OOM/5xx；结果文件字段完整；速度和正确率可复算。

### Phase 2：选择主模型与 workflow

分别跑 COT；只有 TIR 的工具执行有明确质量收益时才保留 TIR。主模型必须满足：

- Pass@1 不低于对照。
- 正确答案中位耗时更短。
- 截断率和崩溃率可接受。

MoE Qwen3.6 的高 TPS 不自动代表高考数学效果更好；Dense Qwen3.8 的速度较低也不自动代表应淘汰。

### Phase 3：仅对胜出模型扫参

按投入回报顺序：

1. reasoning effort / thinking 设置。
2. 输出预算与服务窗口。
3. MTP window。
4. eager 与 CUDA Graph。
5. 必要时才做 checkpoint 或 runtime A/B。

每项先过 Calibration，再用 Holdout 做一次最终确认。

### Phase 4：低优先级研究

- 双 RTX 5090 的 DFlash k=10 历史标杆为 327.05 tok/s，可在主线稳定后复测 k=12/15。
- SGLang + DFlash/DSpark 只有在 vLLM 主线存在明确缺口时继续。
- 多模态、工具调用和并发吞吐属于后续产品负载，不与当前单请求数学基线混测。
